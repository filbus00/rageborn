# Project overview

Rageborn: isometric Diablo-style action RPG for iOS. Unity 6000.6.2f1, URP 2D renderer, new Input System only (`activeInputHandler: 1`, so never use `UnityEngine.Input`). Company Filbus Software, bundle ID `com.filipbusic.rageborn`. On the home screen the app is "Wild Arrow" (2026-10-10, `IosDisplayName` sets only the display name; the product name stays Rageborn).

- `Docs/` is the source of truth for design. Start at `Docs/00-vision-and-scope.md`. If code and docs disagree, ask before changing either. Decisions are logged in `Docs/08-production.md`; log yours there (marked "Claude, to review") when the docs leave a choice open.
- **`Docs/11-engineering-log.md`** holds the full history: how each system was built, what was measured, every bug found and why things are the way they are, including the retired Wrathborn class. This file is the current state only. Search the log before re-deriving something or when a detail is missing here.
- Portrait, iPhone only, iOS 16+, 60 fps. No online features in 1.0.
- One-thumb control: a floating stick is the only input. Attacks and skills fire automatically.
- Diablo 1 structure: a safe town, then a dungeon descended level by level by stairs. **No acts** (the owner, 2026-10-05): one town above one dungeon of 48 levels (24 until 2026-10-12, then 36): crypt 1 to 12, prison 13 to 24, burnt library 25 to 36, caves 37 to 48, a boss every 6 (the Cinder Warden at 6, the Tidewife at 12, the Gaoler at 18, the Hanged Magistrate at 24, Saint Marrow at 30, the Ash Archivist at 36, the Rift Mother at 42, the First Watchman at 48), and newcomers who arrive in town by the deepest depth reached. Enemies are packs placed in rooms that idle until aggro; they never spawn around the player. (The Vigil's road, rifts streaming demons up one long hall, was built on 2026-10-06 and reverted on 2026-10-07: Docs/05 keeps the idea, the log the details.)
- The owner answers design questions one at a time (use AskUserQuestion, one question per call).

# State of the game (2026-10-13)

- **A roguelite** (the owner, 2026-10-13; Docs/08): a run is the whole descent from depth 1, straight down, and a death ends it (the next starts at depth 1). No experience or levelling: every new depth offers three random boons (talent ranks) and she takes one; her level follows the depth. Coins (her gold) are kept between runs and buy permanent upgrades in town. Death loses everything worn and carried; the portal home (anytime from the Bag, 2.5 s) ends the run keeping it all; the stash chest in town keeps what is put in it. Quests, selling, waypoints, portals, stairs up and the corpse are switched off (`Features.Roguelite`, `Features.Quests`), their code kept. See **Roguelite** under Systems.

- **The class is the Wild Arrow** (bows only, the owner's decision of 2026-09-30; Docs/02). The Wrathborn (axes, Rage, passive tree) is retired: his code and assets are kept but unused. Notes in the log describe him where they were not rewritten.
- **The bows branch has run in Unity** (2026-10-03): it compiled clean, 536 of 536 tests pass, Apply Bows Change and the stand-in bake ran, and it plays at 60 fps in the editor, on the simulator and on the owner's iPhone 11 ("It feels really good on the phone"). Steps 6 (legendaries) and 7 (pets) of `Docs/FIRST-RUN.md` were checked in the editor on 2026-10-03: all 24 powers and the pets work. Details in the log.

# Layout

- `Assets/_Project/` holds all game content. `Scripts/Runtime` is `ARPG.Runtime` (namespace `ARPG`), `Scripts/Editor` is `ARPG.Editor`, EditMode tests are in `Tests/EditMode`.
- `ArtSource/` (outside Assets, not imported) holds source models, tools (`ArtSource/tools/*.py`, run with Blender) and the pixel art drop folder.
- `Tools/CompileCheck/` (outside Assets): the compile check for sessions without Unity (below).
- Physics and sorting layer names live in `GameLayers.cs`; `Tools > ARPG > Apply Project Setup` (`ProjectSetup.cs`) applies them and the iOS settings. Keep the two in sync.
- Scenes: `Town` and `Dungeon` are the build (`DungeonSceneBuilder.WriteBuildSettings`); `Sandbox` is a dev scene. They are built by editor menus in order: Create Sandbox Scene, Add Player And Camera, Add Enemies, Add Test Room, Add Combat, Add Survival, Add Loot, Add Inventory Screen, Create Town Scene, Create Dungeon Scene. Most newer systems are created from code at startup instead (directors kept across scenes), so they need no scene step.

# Conventions

- Isometric: Grid cell 1 x 0.5 world units. Gameplay ranges are in **ground space** (1 unit = one tile width; an edge neighbour cell is 0.707 away, a corner one 1.0). `IsoMath` converts ground and world (`GroundToWorld`, `WorldToGround`, `CellToGround`, `GroundToCell`; the Grid sits at the origin). Stick input is unprojected (screen Y doubled) before moving characters.
- Sorting: Custom Axis (0, 1, 0), lower Y draws in front; sprite pivots at the feet; characters and props on the `Entities` layer.
- **Pixel art** (the owner, 2026-09-30): every world sprite is drawn at `PixelArt.PixelsPerUnit` = 40 a unit, snapped to `PixelArt`'s palette with hard alpha, characters and props outlined. `RenderResolution` adds URP's `PixelPerfectCamera` (UpscaleRenderTexture, about 850 px on the long side since 2026-10-04: 2 x 2 pixels on the iPhone 11). She targets only enemies on screen (`PlayerCombat.KeepOnScreen`). Overlay UI stays sharp. Code-made textures that are marked unreadable need `SpriteMeshType.FullRect` and no physics shape, or iOS logs "Sprite outline generation failed".
- Pure logic lives in plain classes with EditMode tests (rules, formulas, rollers, save codec); MonoBehaviours are thin. Keep per-frame code allocation free (pools, reused lists). Read gear and settings live at the point of use rather than caching them.
- Components find each other with `FindAnyObjectByType` when their fields are empty. Statics reset at `SubsystemRegistration`, because domain reload is off.
- `CodeShapeTests` fails on a statement indented as if an unbraced `if` or loop guarded it (it once made a sound play every frame).
- Docs and notes are written in plain, literal English (the owner's style).

# Systems (current)

- **Input and camera**: `FloatingStickInput` (Enhanced Touch; ignores touches that begin on UI via `EventSystem.RaycastAll`; `TestOverride` drives it from scripts, a value longer than 1 counting as outside the ring; `Disengaged` when the thumb leaves the ring, `StickMath.Disengaged`: she holds fire, turns and runs, read as `PlayerController.Disengaged` by combat and the animator), `PlayerController` (Rigidbody2D, `Dash`, slows, Stillness and Momentum through `StanceStacks`; she walks at half speed for up to 0.6 s after each shot or skill, `FiringPace`), `FollowCamera` (lead capped). The `walk` and `dive` sheets bake from `wild_arrow_walk.fbx` and `wild_arrow_dive.fbx` when those exist.
- **Combat** (`PlayerCombat`, on a `Player Combat` scene object): the basic attack is one arrow at the nearest enemy in sight within `BasicRange` (7.5, +1.5 with a longbow, +2 with The Long Silence), 14 units a second, flown in 0.25 pieces so it cannot pass walls. Arrows are `Shot` structs whose **traits** (pierce, fork, ricochet, retarget, ignite and chill chance, certain crit, blood pools, burst) are set in one place, `ApplyGear`, from the skill, the gear and the legendaries. Effects are `ArrowFx` (pooled sprites: trails, blood, sparks, bursts, the pierce arrow's blood trail, burning ground; since 2026-10-11 gore: every hit on a monster splashes (`Wound`, from `EnemyController.TakeDamage`), wounded and bleeding monsters drip, kills burst with chunks and a pool, and blood stays 30 s as `BloodArt` pixel splats, 260 at most). Aim (2026-10-08, `AimRules`): by `PlayerController.StickPush`, 100 percent to a third of the push, 80 to two thirds, 60 past; arrows but Homing ones leave off target by a random angle rolled once per shot (`PlayerCombat.RollStray`, applied in `NewArrow`); `AimCone` draws it as a faint wedge toward her target, white, amber, red. Momentum shots and cover (2026-10-17, `Combat/MovementRules.cs`): Momentum stacks speed her shots and lengthen her reach; beside a wall or prop she is in cover on that side (projectiles from it break, `EnemyProjectiles`), with an ambush shot after 0.5 s (`CoverShield` over her head). # Working with Unity (the owner's Mac)

- `Tools > ARPG > Run EditMode Tests` writes `Logs/EditModeTests.txt`. The Unity MCP bridge can run menu items but not the test runner API or `AssetDatabase.DeleteAsset`.
- `BackgroundRefresh` recompiles edits made from outside while the editor is in the background; do not edit scripts during play mode (a recompile mid-play drops runtime state).
- Stepping play mode from a script with the editor in the background: pause, set `Time.captureDeltaTime = 1/60f` and call `EditorApplication.Step()` in a loop; reset it after. Captures rendered by hand bypass the Pixel Perfect Camera (disable it and set the camera rect and size first) and do not show overlay UI: check the look on the simulator.
- `GC.GetAllocatedBytesForCurrentThread()` returns 0 in the editor; measure allocations with `GC.GetTotalMemory(false)` over thousands of iterations.
- Opening a scene in single mode unloads assets nothing references yet: editor builders reload assets by path after `OpenScene`.
- Sprite bakes are incremental (2026-10-11, `SpriteBakeCache` in Library/SpriteBakeCache): Bake Wild Arrow renders only sheets whose models, clips, settings or bake version changed (9 s when nothing did); Bake Wild Arrow (Full) renders all (45 min); Mark Wild Arrow Sheets As Baked seeds the cache from the sheets on disk. **Before any bake, run Report Stale Wild Arrow Sheets** (counts, draws nothing); editing bake scripts no longer invalidates sheets, bump `SpriteBaker.BakeVersion` only when a change alters the pixels. A bake has a Cancel button. The first body is posed every frame as the occluder of gear layers. The Bag's figure is a separate portrait bake (Bake Wild Arrow Portrait: one still front frame per look, smooth, 6x, Resources/Characters/wild_arrow_portrait).
- Baked sheets are cropped to the area their frames draw in, with FullRect sprites (`SheetTrimmer`, run by the bake; `Tools > ARPG > Sprite Bake > Trim Character Sheets` for old sheets): the app went from 1.4 GB to 741 MB. The retired Wrathborn's sheets are in `Art/RetiredSheets`, outside Resources.
- A `Resources` folder ships everything in it, and a rebake does not delete files it no longer writes; remove stale sheets by hand.
- Do not hand-edit `ProjectSettings/*.asset` while the editor is open; apply settings through editor scripts.
- Builds: `Tools > ARPG > Build iOS Simulator / Device (Xcode project)`, then xcodebuild (scheme `Unity-iPhone`, **configuration Release**: Debug compiles the game's C++ unoptimised, a dungeon load took 6.3 s instead of 4.1). Load times: `LoadTimer` logs `[ARPG] Load N ms` by phase in development builds. The owner's phone install commands, device ids and the simulator's tap quirks are in the log under "Builds and performance".
