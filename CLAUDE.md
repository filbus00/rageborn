# Project overview

Rageborn: isometric Diablo-style action RPG for iOS. Unity 6000.6.2f1, URP 2D renderer, new Input System only (`activeInputHandler: 1`, so never use `UnityEngine.Input`). Company Filbus Software, bundle ID `com.filipbusic.rageborn`.

- `Docs/` is the source of truth for design. Start at `Docs/00-vision-and-scope.md`. If code and docs disagree, ask before changing either. Decisions are logged in `Docs/08-production.md`; log yours there (marked "Claude, to review") when the docs leave a choice open.
- **`Docs/11-engineering-log.md`** holds the full history: how each system was built, what was measured, every bug found and why things are the way they are, including the retired Wrathborn class. This file is the current state only. Search the log before re-deriving something or when a detail is missing here.
- Portrait, iPhone only, iOS 16+, 60 fps. No online features in 1.0.
- One-thumb control: a floating stick is the only input. Attacks and skills fire automatically.
- Diablo 1 structure: a safe town, then a dungeon descended level by level by stairs. Enemies are packs placed in rooms that idle until aggro; they never spawn around the player.
- The owner answers design questions one at a time (use AskUserQuestion, one question per call).

# Layout

- `Assets/_Project/` holds all game content. `Scripts/Runtime` is `ARPG.Runtime` (namespace `ARPG`), `Scripts/Editor` is `ARPG.Editor`, EditMode tests are in `Tests/EditMode`.
- `ArtSource/` (outside Assets, not imported) holds source models, tools (`ArtSource/tools/*.py`, run with Blender) and the pixel art drop folder.
- `Tools/CompileCheck/` (outside Assets): the compile check for sessions without Unity (below).
- Physics and sorting layer names live in `GameLayers.cs`; `Tools > ARPG > Apply Project Setup` (`ProjectSetup.cs`) applies them and the iOS settings. Keep the two in sync.
- Scenes: `Town` and `Dungeon` are the build (`DungeonSceneBuilder.WriteBuildSettings`); `Sandbox` is a dev scene. They are built by editor menus in order: Create Sandbox Scene, Add Player And Camera, Add Enemies, Add Test Room, Add Combat, Add Survival, Add Loot, Add Inventory Screen, Create Town Scene, Create Dungeon Scene. Most newer systems are created from code at startup instead (directors kept across scenes), so they need no scene step.

# Conventions

- Isometric: Grid cell 1 x 0.5 world units. Gameplay ranges are in **ground space** (1 unit = one tile width; an edge neighbour cell is 0.707 away, a corner one 1.0). `IsoMath` converts ground and world (`GroundToWorld`, `WorldToGround`, `CellToGround`, `GroundToCell`; the Grid sits at the origin). Stick input is unprojected (screen Y doubled) before moving characters.
- Sorting: Custom Axis (0, 1, 0), lower Y draws in front; sprite pivots at the feet; characters and props on the `Entities` layer.
- **Pixel art** (the owner, 2026-09-30): every world sprite is drawn at `PixelArt.PixelsPerUnit` = 40 a unit, snapped to `PixelArt`'s palette with hard alpha, characters and props outlined. `RenderResolution` adds URP's `PixelPerfectCamera` (UpscaleRenderTexture, about 600 px on the long side). Overlay UI stays sharp. Code-made textures that are marked unreadable need `SpriteMeshType.FullRect` and no physics shape, or iOS logs "Sprite outline generation failed".
- Pure logic lives in plain classes with EditMode tests (rules, formulas, rollers, save codec); MonoBehaviours are thin. Keep per-frame code allocation free (pools, reused lists). Read gear and settings live at the point of use rather than caching them.
- Components find each other with `FindAnyObjectByType` when their fields are empty. Statics reset at `SubsystemRegistration`, because domain reload is off.
- `CodeShapeTests` fails on a statement indented as if an unbraced `if` or loop guarded it (it once made a sound play every frame).
- Docs and notes are written in plain, literal English (the owner's style).

# Systems (current)

Each line names the main types; the log has the details and history.

- **Input and camera**: `FloatingStickInput` (Enhanced Touch; ignores touches that begin on UI via `EventSystem.RaycastAll`; `TestOverride` drives it from scripts, a value longer than 1 counting as outside the ring; `Disengaged` when the thumb leaves the ring, `StickMath.Disengaged`: she holds fire, turns and runs, read as `PlayerController.Disengaged` by combat and the animator), `PlayerController` (Rigidbody2D, `Dash`, slows, Stillness and Momentum through `StanceStacks`; she walks at half speed for up to 0.6 s after each shot or skill, `FiringPace`), `FollowCamera` (lead capped).
- **Combat** (`PlayerCombat`, on a `Player Combat` scene object): the basic attack is one arrow at the nearest enemy in sight within `BasicRange` (7.5, +1.5 with a longbow, +2 with The Long Silence), 14 units a second, flown in 0.25 pieces so it cannot pass walls. Arrows are `Shot` structs whose **traits** (pierce, fork, ricochet, retarget, ignite and chill chance, certain crit, blood pools, burst) are set in one place, `ApplyGear`, from the skill, the gear and the legendaries. Effects are `ArrowFx` (pooled sprites: trails, blood, sparks, bursts, the pierce arrow's blood trail, burning ground). Hit math is `CombatFormulas.HitDamage` through `Strike`/`Damage`; "more damage" from legendaries is `ArrowMore`. `GroundMark` holds blood pools and burning ground.
- **Focus** (`FocusPool`): full on level load, 6 a second, +4 per basic arrow that hits; drawn by `RageArc` in blue. Skill costs go through `PlayerCombat.CostOf` (legendaries change them). `SkillDefinition.rageCost` keeps its old name and is the Focus cost.
- **Skills** (`WildArrowSkillsBuilder`, `Data/Skills`, `Resources/ClassSkills.asset`), nine, all unlocking at level 1 (the owner, 2026-10-04): Split Arrow (`Volley`), Pierce Arrow (`PierceShot`), Homing Arrow (`HomingShot`), Explosive Arrow (`ExplosiveShot`), Kill Shot (`KillShot`), Knockback Shot (`KnockbackShot`), Barrage (`Barrage`), Wild Frenzy and Hunter's Breath (both `Buff`). Class order (cast priority of an unchosen loadout) in that order; the first four fill an unchosen loadout. Auto-cast from the four-slot `SkillLoadout` with per-slot `SkillTrigger`s; `SkillLevels` from skill points; the loadout screen opens at level 1.
- **Attributes** (`AttributePoints`, `CharacterAttributes`, the Bag's Stats tab `StatsScreen`): 5 points a level on Strength, Agility, Vitality, Speed, Focus. The passive tree is hidden, not deleted.
- **Pets** (`Pets/`): Wolf, Raven, Boar bought at the `PetVendor` in town (cell (5, 1)); `PetController` follows, bites by `PetTargeting`, draws melee hits, fetches loot, gets knocked out; behaviour toggles on `PetVendorScreen`.
- **Enemies**: `EnemyManager` owns the pool, the `NavGrid` (baked from tilemaps), one `FlowField` from the player and a `SpatialHash`, and ticks every `EnemyController` (no Rigidbody, ground space, moves in pieces of 0.25). `EnemyDefinition` holds tuning; `EnemyPack` spawns members on load and records kills. Ranks Normal, Champion, Elite (modifiers Hasted, Vampiric, Frozen), Boss. Act 1: husk (swarmer), ghoul (brute, ground slam), bandit archer (aim line, then arrow); from depth 4 skeletons (in husks' place) and cultists (fire bolts, in archers' place), `PackComposition`. Ranks and the boss are baked at their `VisualScale` (`EnemyAnimationSet.BakedScale`), not stretched. Ailments: bleed, `BurnStacks`, `ChillMeter` (freeze), the pet's mark. Baked sheets animate them (`EnemyAnimationSet`).
- **Act boss**: the Cinder Warden (`CinderWardenFight`, scripted phases, `StaggerMeter`, `BossBar`) in the arena of depth 6.
- **Dungeon**: `DungeonGenerator` (pure, seeded; connected halls, `Version` 5: bump it whenever the same seed would build a different level), `DungeonDressing` (props, decals), `DungeonLevel` paints it in Awake. 6 levels per act, enemy levels 1, 2, 3, 4, 5, 7 (`DungeonRules`). Camera-side walls are cut low (`WallRules`). `Minimap`, chests, waypoints, the Waystone, the Wanderer's Portal Tome and town portals (`TravelDirector`, `SceneTravel`).
- **Dungeon art**: `DungeonArt` draws floors, walls and props in code, unless an imported piece exists in `Resources/Art/Dungeon` (`Tools > ARPG > Import Pixel Art`, `PixelArtImporter`, names in `ArtNames`, drop folder `ArtSource/pixel/dungeon/` with its README).
- **Modelled props** (2026-10-04): `ArtSource/tools/props/` builds props in Blender from code and renders them from the game's camera at 4x (`render_props.py`, `preview.py`; details in the log). Dungeon props, walls and decals go to `ArtSource/pixel/dungeon` (Import Pixel Art); larger pieces (stairs, chests, waypoints, the ritual circle, town buildings) to `ArtSource/pixel/world` with `manifest.json`, imported by `Tools > ARPG > Import World Art` (`WorldArtImporter`) to `Resources/Art/World`, loaded by `WorldArt`. Props include a bucket and a lit standing torch; one combat or elite room in four has a summoning circle (`DungeonLayout.Rituals`). The town is dressed from code by `TownDressing` from `TownLayout` (houses, tents, campfire, well, stall, pen, lamps, trees; footprints block on the Obstacle layer). Floors are continuous ground textures (`ground.py`: one seamless 4 x 4 cell repeat a style cut into 16 pieces, picked by `DungeonArt.VariantAt`; tinted by the smooth `LightingRules.GroundShade`), and `DungeonLevel.DressWalls` hangs torches, chains, banners, candles, skulls and cobwebs on about one wall in nine facing a room (by a hash of the cell). `gear.py` models the bows and quivers (every look in `AppearanceRules`), `boss.py` the Cinder Warden on the ghoul's rig (`EnemyBakeSetup.ClipAvatarFrom`).
- **Items** (`Item`, immutable): ten slots. The enum names stay for saves: `Weapon` is the short bow, `TwoHandWeapon` the longbow, `Shield` the quiver, `OffHand` and `Ring2` are only places to wear things. `GripRules` holds the bow numbers. `AffixTable`/`AffixRoller`: tiers T1 to T5 gated by item level; affixes 90 to 100 (pierce, fork, burn damage, range, arrow speed, pet, +1 skill arrow) read through `EquipmentState.AffixTotal`; some are fixed values or gated by item level. Starting kit: a Common bow and quiver. The backpack (`Inventory`) is a 10 x 6 grid, auto-packed: `ItemSize` per kind (bows 2 x 4, quiver and chest 2 x 3, helm, gloves, boots 2 x 2, belt 2 x 1, jewellery 1 x 1), first fit row by row, a full repack when a new item fits nowhere, `TrySwap` for all-or-nothing equips; refused sizes are cached until the grid changes, since auto-loot asks every frame. Placements are not saved; a loaded backpack repacks in its saved order.
- **Loot** (`LootRoller`, pure and seeded; `LootDirector`): drop chances and rarity weights from Docs/03, bad luck protection, `LootSource` per rank. A Legendary becomes a named one from `Legendaries` (24, each with a power, a home source twice as likely, an archetype; `legendaryRandom` is its own stream) with smart drops toward places with no legendary worn. Powers are checked with `EquipmentState.Wears(id)` where they land. `PowerScore` drives upgrade arrows (it ignores powers and conditional affixes). Auto-loot is `PlayerLoot` (rules in `AutoLootRules`): gold at once; an item only 1.5 s after it lands (`ItemDelaySeconds`, `LootDrop.SecondsSinceLanding`) and when the player's pick-up rule wants it (`PickupRule` in `GameSettings`, the Settings Loot row: Everything, Magic and better (default), Rare and better, Upgrades only; Legendaries and upgrades always; `LootDrop.IsWanted`, rechecked once a second; the pet fetches only wanted drops). Every item on the ground shows its name in its rarity colour (a `TextMesh`, dimmed when the rule leaves it), and a pickup calls the name out over the character. Items hop out of the kill (0.6 units, never through a wall: `NavGrid.HasLineOfSight`), a Rare or better marker flares on landing, and `LabelLayout` (pure) lifts names that would overlap, laid out by `LootDirector` four times a second.
- **Town NPC bodies** (2026-10-03): `NpcFigure` plays a baked idle from `Resources/Characters/<name>` (8 directions, turned toward her within 6 units; the placeholder figure until baked), baked by `NpcBakeSetup` (`Tools > ARPG > Sprite Bake > Bake NPCs`) from `Art/Models/NPCs/<name>/<name>.fbx`, a Mixamo idle with skin, and `<name>_albedo.png`: `merchant` (the owner's Meshy pack bearer) and `pet_vendor` (a beast tamer).
- **Enemy looks**: husk, ghoul and bandit archer from the owner's Mixamo models; `husk_champion` and `husk_elite` recoloured; the Cinder Warden modelled in Blender (`ArtSource/tools/props/boss.py`).
- **Merchant** (the owner, 2026-10-02, reversing Q26's "no vendor"): `Merchant` at town cell (-4, 1), placed by `PetDirector`, buys only. Walking up calls `InventoryScreen.OpenAtMerchant`: the `ItemSheet` offers Sell (`ItemSheet.Selling`) in place of Discard, and a row sells all Commons, Magic or Rares on a second tap. Prices and the bulk rule (upgrades and named legendaries kept) are in `SellRules`; `GameSession.Sell`, `BulkSale`, `SellAll`.
- **UI** (built in code, `UiStyle` look; frames and fills are pixel art drawn in code, `UiArt`): `InventoryScreen` (the Bag, the game's only pause, tabs Inventory, Skills, Stats, Codex, Settings; tiles show `ItemIcons`, pixel pictures drawn by `ItemIconArt` (pure) the size of the item's block; gear is dragged onto the slot it fits, and worn gear onto the backpack to take it off: `ItemDrag`, `ItemDropTarget`, `GameSession.EquipFromInventory(item, place)`; the drop raycasts at the release point itself, since on iOS the touch's own result is cleared when the finger lifts), `ItemSheet` (power, home, Build tag), `CodexScreen` (with a DEV: give button in debug builds), `ForgeScreen`, `LoadoutScreen`, `PetVendorScreen`, `SettingsScreen`, `WaypointScreen`, `HintBanner`, HUD laid out by `HudLayout`.
- **Forge: switched off** (the owner, 2026-10-02: focus on killing mobs and looting gear). `Features.Forge` is false: the smith (`ForgeNpc`) hides itself, elites and the boss grant no materials, the Forge hint and the Bag's materials row are gone. `ForgeRules`, `ForgeScreen`, materials in the session and save stay untouched for later. - **Session and saving**: `GameSession` (pure) is everything that survives a scene change; `GameSession.Current` is replaced on every play. `SaveData`/`SaveCodec`/`SaveStore`: one JSON file, atomic writes, 3 backups, enums by name, **format 13** (legendaries and the Codex). In the editor saving is off unless `Tools > ARPG > Save > Save In Editor` is ticked. A loaded game starts in town.
- **Progression**: `Experience`, `CharacterProgress` (levels 1 to 60), `ExperienceDirector`.
- **Also**: `AutoPotion` (35 percent, 3 charges), `Onboarding` (ghost thumb, Forge hint, first Legendary), `GameSettings`/`SettingsDirector` (account file), `Sfx` (designed WAVs from `ArtSource/tools/audio/make_sfx.py` in Resources/Audio/Sfx, else the `SoundSynth` placeholder) and `MusicSynth` (synthesized music), `LightingDirector` (dark dungeon, player ember, 2D lights), `SpriteEffects` (hit flash, death dissolve), `DevShortcuts` (DEV stairs to depth 3 and the boss in town), `PerfOverlay`, `DevAutopilot` (plays act 1 by itself), the balance report.
- **Characters on screen** (sheets cached per look; equipping drops only the sheets of looks no longer worn and preloads the clips the bake's timing file lists; never `Resources.UnloadUnusedAssets` on equip, it froze the game 1.2 to 2.2 s): baked from 3D models (`SpriteBaker`, `SpriteBakeJob`, `Tools > ARPG > Sprite Bake`): `LayeredCharacterSprite` stacks body, helm, off-hand and weapon sheets from `Resources/Characters/<character>`; `PlayerSpriteAnimator` picks the animation (`LocomotionRules`). # Working without Unity (cloud sessions)

- `Tools/CompileCheck/run.sh` compiles Runtime, Editor and the tests with the .NET SDK (installed from the Ubuntu archive; NuGet and Microsoft's download hosts are blocked) against stand-ins of the Unity API, as C# 9 on .NET Standard 2.1, then runs the EditMode tests. **Run it before every push of C# changes.** A missing stub member is fixed in `Tools/CompileCheck/Stubs` with Unity's real signature, never by changing game code. It checks compile errors and pure logic only.
- Say plainly in commits and to the owner what was compiled, tested, or not run in Unity.

# Working with Unity (the owner's Mac)

- `Tools > ARPG > Run EditMode Tests` writes `Logs/EditModeTests.txt`. The Unity MCP bridge can run menu items but not the test runner API or `AssetDatabase.DeleteAsset`.
- `BackgroundRefresh` recompiles edits made from outside while the editor is in the background; do not edit scripts during play mode (a recompile mid-play drops runtime state).
- Stepping play mode from a script with the editor in the background: pause, set `Time.captureDeltaTime = 1/60f` and call `EditorApplication.Step()` in a loop; reset it after. Captures rendered by hand bypass the Pixel Perfect Camera (disable it and set the camera rect and size first) and do not show overlay UI: check the look on the simulator.
- `GC.GetAllocatedBytesForCurrentThread()` returns 0 in the editor; measure allocations with `GC.GetTotalMemory(false)` over thousands of iterations.
- Opening a scene in single mode unloads assets nothing references yet: editor builders reload assets by path after `OpenScene`.
- A `Resources` folder ships everything in it, and a rebake does not delete files it no longer writes; remove stale sheets by hand.
- Do not hand-edit `ProjectSettings/*.asset` while the editor is open; apply settings through editor scripts.
- Builds: `Tools > ARPG > Build iOS Simulator / Device (Xcode project)`, then xcodebuild (scheme `Unity-iPhone`). The owner's phone install commands, device ids and the simulator's tap quirks are in the log under "Builds and performance".
